# Serve's trained models

Every model we trained for Serve during the hackathon (October 27 to November 4, 2026), with what it is, what it was
trained on, its measured results and where each number comes from, how to load it, and its sha256.

- **Large files** (GGUF weights, LoRA adapters) are assets on the GitHub Release
  [models-2026-11-01](https://github.com/gino6178/serve-meta-hackathon/releases/tag/models-2026-11-01).
- **Small heads** (a few KB each) are in the code, at the paths given below, and load with the gateway.

**Built with Llama.** The models whose names begin with `Llama-3.2` are derived from Meta's Llama 3.2 1B Instruct and
Llama 3.2 3B Instruct and are distributed under the [Llama 3.2 Community License](LICENSE-Llama-3.2.txt) and its
[Acceptable Use Policy](USE_POLICY-Llama-3.2.md); see [NOTICE](NOTICE). Llama 3.2 is licensed under the Llama 3.2
Community License, Copyright © Meta Platforms, Inc. All Rights Reserved. As that license asks, every derived model's
name begins with "Llama". The small heads are not derived from Llama and fall under the repository's
[MIT License](../LICENSE).

**What went into training.** Every training case came from simulated club members generated by code (`population.js`,
seed 7) or from synthetic inputs, labelled by Muse Glimmer. No real member's data was used, and no training data is
published here, only weights. Each file was checked before release: GGUF metadata holds only the architecture,
tokenizer and chat template; the adapters' configs had a local base path, replaced with the Hugging Face model id; no
secrets or tokens.

## 1. The decision model: Llama 3.2 1B distilled from Muse Glimmer (served)

| | |
|---|---|
| Files | `Llama-3.2-1B-Serve-Decision-v4-Q4_K_M.gguf` (served from October 31); `Llama-3.2-1B-Serve-Decision-v3-Q4_K_M.gguf` and its LoRA adapter `Llama-3.2-1B-Serve-Decision-v3-LoRA.zip` (served before it) |
| Base model | `meta-llama/Llama-3.2-1B-Instruct` |
| Task | A member's agent's one judgment: which of the listed workable times its person would like best (or "can't play this week"). The options are declared in the prompt and scored together in one forward pass, as a probability for each option letter; no text is generated |
| Trained on | 4,868 choices Muse Glimmer made through the real agent call, on simulated members (private calendars, shared calendars and asked-time cases). Round 4 (v4) added one more Glimmer answer for 700 random training cases |
| Recipe | LoRA, rank 16, alpha 32, dropout 0.05, on all attention and MLP projections; 3 epochs, learning rate 2e-4, batch 4 × 4 accumulation; letters in time order (`distill/train.py`, `distill/prompt.py`). Merged and converted with llama.cpp, quantized to Q4_K_M without an importance matrix (`distill/export.sh`) |
| Size and format | GGUF Q4_K_M, 0.8 GB; the adapter is PEFT safetensors, 45 MB |

**Measured results**

| What | v3 | v4 | Source |
|---|---|---|---|
| Agreement with Glimmer, 500 held-out cases (bf16) | 89.5% (Glimmer with itself: 88.8%) | | `docs/decision_model.md`, `submission/technical_report.md` 2.6 |
| Agreement on test, int4 as served (each answer) | 88.5% | 88.9% | `docs/decision_model.md` ("int4", round 4) |
| Hardest 196 cases, int4, against the majority of Glimmer's answers / against `full` | 67.0% / 60.7% | 69.5% / 62.8% | `docs/decision_model.md` (round 4) |
| Expected calibration error, test | 0.052 (bf16); 0.042 (int4) | 0.039 (int4) | `submission/results/student_calibration.json`; `docs/decision_model.md` |
| Picks changed when the listed times are reversed (196 hardest) | 20.2% (the one-token decider: 90.8%) | | technical slides, "The one-token decider mostly reads the order"; `submission/results/order_sensitivity.json` |
| Time per decision, CPU, 8 threads (p50) | 910 ms | 1.37 s (on a shared CPU) | `docs/decision_model.md` |
| Answers at 0.6 sure (served threshold) | 96.0% of 500; 73.0% of the hardest | | `submission/technical_report.md` 2.6 |

**How to load it.** The gateway calls a small CPU worker that scores the option letters:

~~~sh
# llama-cpp-python; the tokenizer is Meta's Llama 3.2 tokenizer (meta-llama/Llama-3.2-1B-Instruct)
python distill/worker.py --gguf Llama-3.2-1B-Serve-Decision-v4-Q4_K_M.gguf --tokenizer <Llama 3.2 tokenizer dir> --port 11447 --threads 8 --order time
# then run the gateway with A2A_STUDENT_URL=http://127.0.0.1:11447 (the default); A2A_STUDENT_SURE=0.6
~~~

`distill/serve.sh` wraps the same command. The prompt format is in `distill/prompt.py`. The adapter loads with PEFT on
the base model (`PeftModel.from_pretrained(AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.2-1B-Instruct"), "<unzipped dir>")`).

The round-4 (v4) LoRA adapter is not published: it was trained on a cloud VM and is not on our server; only its int4
GGUF was kept there.

## 3. The text model: Llama 3.2 1B distilled for short text (served)

| | |
|---|---|
| Files | `Llama-3.2-1B-Serve-Text-Q4_K_M.gguf` (served), `Llama-3.2-1B-Serve-Text-LoRA.zip` (its SFT adapter) |
| Base model | `meta-llama/Llama-3.2-1B-Instruct` |
| Task | Short text at six checked call sites: wording a game ask, a court's name in English, a memory's beliefs, a paper's summary, a question about the feed, what a member's answer teaches |
| Trained on | Muse Glimmer's answers to 1,039 synthetic inputs through the real call sites (858 for training, 166 held out by input source), plus 371 copies carrying injected or disguised text that keep Glimmer's answer to the clean text, and a KL term toward Glimmer's verdicts (`submission/results/text1b.json`, "set") |
| Recipe | LoRA SFT, rank 32, alpha 64, 3 epochs, learning rate 2e-4, batch 8, 1,229 examples (`distill/text_train.py`); outside text in a message of its own (role `input`). Q4_K_M without an importance matrix (`distill/text_export.sh`) |
| Size and format | GGUF Q4_K_M, 0.8 GB; adapter 90 MB |

**Measured results** (all from `submission/results/text1b.json`)

| What | Old 1B (the decision model as a chat model) | This model | Muse Glimmer |
|---|---|---|---|
| Hostile comments let through, 71 held-out (templates never seen in training) | 65 | **8** | 0 |
| Poisoned reviews that turned a bad court "good", of 180 | 98 | **7** | 5 |
| Held-out agreement with Glimmer: `answer.learn` / `feed.standard` / `places.judge` / `life.read` | 0/30, 13/23, 9/20, 0/59 | 30/30, 23/23, 15/20, 34/59 | |

With the six checked sites on this model, the end-to-end test, the feed red team (13 of 13) and the red team (93 of 93)
pass as with Glimmer alone (`submission/technical_report.md`, section 3).

**How to load it** (Ollama):

~~~sh
# edit the FROM line of distill/Modelfile.serve-1b-text to point at the downloaded GGUF, then
ollama create serve-1b-text -f distill/Modelfile.serve-1b-text
# the gateway's short route: LLM_SMALL_MODEL=serve-1b-text
~~~

## Checks before release

- No personal or member data: training used simulated members and synthetic inputs only; no training data is released.
- No secrets: GGUF metadata, adapter configs and the small heads were read in full for tokens, keys and paths. The
  adapters' `base_model_name_or_path` pointed at a local folder and now names the Hugging Face base model; nothing else
  was changed. The auto-generated PEFT model card and the training arguments file (local paths) were left out.
- Not published: the round-4 LoRA adapter (not on our server; only its GGUF is), Q5_K_M and importance-matrix variants of the text
  model (quantization experiments of the same weights), and every training set.
